# Yggdrasil v1.1.1

Version 1.1.1 adds Codex builders: project managers, team leads, workers and senior users can run on Codex, on macOS, with codex-cli 0.170.0. Each Codex team lead and its workers work in a private clone of their lane. Yggdrasil's own code outside the sandbox does not read or change the files in it: it opens the box only by descriptor, and every read or change of the clone runs in a sandboxed helper. The one exception is the Codex CLI's own `codex sandbox` command, which starts each helper step outside the sandbox, with your rights and the box as its working folder; how it handles project settings an agent left in the box has not been tested. Their work reaches the project only through a receive step in the home that the agent cannot reach. v1.1.0 refused Codex for every role but the project reviewer.

A project reviewer on Codex now signs in only through `ygg codex login`, `CODEX_API_KEY` or a model provider of your own (one with its own key, or a local one that needs none), and the first two work only on macOS with codex-cli 0.170.0; see [Upgrading from v1.1.0](#upgrading-from-v110).

## What is in

- **Codex builders, each in its own private clone.** A Codex team lead and its workers share one clone of their lane, in a box folder under `.ygg-worktrees/<project>/lane/`. The box is the Codex sandbox's only writable folder, apart from the session's relay folder: not the home's git folder, the hooks, Yggdrasil's state or tracker, `/tmp`, your temporary folder or the network. A Codex PM, and a senior user with nothing in test, work in an empty scratch folder; a testing senior user gets a fresh clone of the lane head, which is never received. See [Launchers](../launchers.md).
- **A Codex home written by Yggdrasil.** Every Codex session runs with its own Codex home, holding only some settings of your model provider and, when you have Yggdrasil's own Codex login, links to it. Other provider settings are not copied, and your own Codex login is not read or copied (see [Configuration](../configuration.md#agent-environment)). Your MCP servers, hooks, rules, skills, approval settings and project trust in `~/.codex` do not reach agents, and subagent tools and skill listings are switched off.
- **Yggdrasil's own Codex sign-in.** `ygg codex login` (with `--device-auth` for a machine without a browser, or `--with-api-key`), `ygg codex status` and `ygg codex logout` sign Codex agents in and out through Codex's own flow, into one login folder for your user (`agent_codex_login_dir`, by default `~/.config/yggdrasil/agent-codex`). Yggdrasil never reads, copies, prints or sends the login. The three commands are yours alone. `ygg codex logout` is refused while Codex sessions that use the login are running. See the [CLI reference](../cli-reference.md#codex-sign-in).
- **One shared login per user.** Every Codex session links to that one login, so a refreshed ChatGPT sign-in is seen by every session, and your own Codex folder (`~/.codex`) and its login are not used. A ChatGPT account or an API key, whatever `codex login` accepts, signs in the same way.
- **The API-key route.** An API key in `CODEX_API_KEY` in the conductor's environment now reaches Codex agent sessions (a project reviewer's only on macOS with codex-cli 0.170.0), and Codex uses it before any stored login. It never reaches Claude Code sessions, relayed `ygg` calls, `t3` commands or Yggdrasil's sandboxed helper. A model provider with its own key, such as a proxy, works as before. `ygg doctor` shows which route a Codex session would use, and a Codex launch with none raises a log-class `ygg-codex-sign-in` alert and a line in `ygg status`. See [Getting started](../getting-started.md#what-you-need), which also says what OpenAI and Anthropic advise for each route.
- **Keys hidden from agents' commands.** Codex keeps `CODEX_API_KEY`, `OPENAI_API_KEY`, `CODEX_ACCESS_TOKEN` and your provider's key variables for its own sign-in, and Yggdrasil's config tells it to leave them out of the commands it runs for the agent. Redaction now also hides JSON Web Tokens, older `sk-` OpenAI keys and `refresh_token` values, the shapes a copied Codex login holds, and the lane check refuses a commit that adds one of them to a file when the repository did not already hold it.
- **A relay for `ygg` calls.** A Codex agent's `ygg` calls are run outside the sandbox by its supervisor, with the agent's own identity and only the verbs that node may run, while the agent is still running.
- **Pause and stop reach Codex builders.** While a programme is paused or a node is stopped, the relay refuses a Codex builder's new `ygg` calls with the same messages the Claude Code guard hook gives. Under pause, a call already being served finishes; a stop cancels it and reports it as stopping, with its outcome unknown. Pause does not halt a running Codex builder: it keeps working in its box until it ends, so use `ygg stop` to end it now. Stop signals a Codex builder's process group as it does a Claude Code agent's.
- **The receive step.** `ygg wp ready` and `ygg lane sync` take a Codex lane's new commits into the home only after the full lane check has run again in the home, on the home's own copies, and only by moving the lane forward. A commit made with its hooks skipped is refused there.
- **Commit-time checks in the clone.** Yggdrasil's git hooks run inside the clone as they do in a worktree lane, without writing anything, and refuse a commit or push while the agent has unread mail. `--no-verify` does not skip the lane check: the reference-transaction hook runs it over the commits a branch move adds. A hook that needs a commit the home holds reads it for that one git process and stores nothing in the clone.
- **Quarantined boxes.** A box is quarantined when its lane is cleaned up after a merge, when a package on it is cancelled, when its clone is odd, or after an interrupted step. A quarantined box is never moved, edited or deleted: it stays beside the live one, and `ygg status` lists the live box first, marked `live; do not remove`, then every quarantined box, marked `quarantined <date>`, with the reason and what a report inside it saw. Yggdrasil never says a box is empty. See [Security](../security.md#quarantined-boxes) for how to take work out and when you may remove a box.
- **Odd clones are replaced, never repaired.** A clone with a link, FIFO or other special file in its git folder, a dependency on something outside it, a changed repository format, a missing or moved given commit, or a check that ran out of time is quarantined where it stands and replaced at the next launch into the lane, once no activation of the lane runs. The agent is told where its old clone is kept. For every cause above except a check that ran out of time, a lane replaces its clone at most three times in 24 hours; after that the lane holds and its launches are refused with an alert until one of those boxes is a day old or moved out of the lane folder. A check that ran out of time is not counted, because a slow disk or a large box can cause it, and it never holds the lane on its own; instead the third time-out in 24 hours, and every third after it, raises a `ygg-clone-replaced` alert.
- **Cancel and cleanup keep everything.** `ygg wp cancel` on a Codex lane quarantines the box, uncommitted changes included, and builds a fresh clone at the drop point. An interrupted cancel is finished with `ygg wp cancel <project> --finish <lane node>`, which quarantines the box of the generation the cancel recorded and never builds a clone at the pre-cancel head.
- **A pinned Codex version.** Codex builders run only on a probed platform and Codex version, today darwin with codex-cli 0.170.0; any other version or platform is refused at launch, at a conductor launch and in the receive step. The project reviewer is not pinned: its version is recorded, and `ygg status` shows `unprobed` on a review run with another version. `scripts/codex-reprobe` runs the probes a new Codex version needs before it can be added.
- **Fixed: upgrading from v1.0.0 in the middle of an exception replan.** If a project's exception plan was rejected under v1.0.0, the follow-up decision v1.0.0 created now counts once you answer it with `replan`, whether you answered it before or after the upgrade, and the project manager can mark the new plan ready. A decision raised later with the same question does not count. v1.1.0 asked you to finish such a replan before upgrading; that is no longer needed.
- **The demo's check for an earlier demo is stricter.** At start, `ygg demo` looks in the temporary folder for a demo left behind. It now looks only at folders you own with the demo's own name pattern, reads their marker without following links or waiting on special files, and quotes the folder name in the cleanup command it prints. On a shared Linux machine another user can no longer make your demo hang or print a command of their choosing.
- **Docs.** The README, Getting started, Configuration, Launchers, Security and Contributing pages describe Codex builders. The Security and Configuration pages now say that proxy settings reach agents unchanged, so a proxy address with a user name and password in it reaches them too, and that such credentials are not hidden by `ygg profile show` or `ygg config explain`.

## Known limits that stay

- **macOS only.** Codex builders are refused on Linux until the sandbox there has been re-probed.
- **Git programmes only.** Codex builders are refused in a programme that is not a git repository, such as a `vault-docs` programme, before anything is reserved.
- **No network for Codex builders.** A project whose setup needs downloads cannot build on Codex.
- **No collapsed projects on Codex.** A Codex worker must belong to a team lead, and a Codex package must be on a team lead's lane.
- **One runtime per lane.** A lane is a worktree lane (Claude) or a clone lane (Codex) from the day it is made; converting a lane is not supported.
- **What the sandbox cannot close.** The Codex CLI's `codex sandbox` command starts each helper step outside the sandbox, with your rights and the box as its working folder, and nothing yet tests that it ignores project settings an agent left in the box. A background process an agent started can outlive the orphan scan and keep changing its own old box until it exits, though never the next box, the home or anything outside its box. Lane code runs outside any sandbox at the merge check, after review and acceptance. Every file in a box, live or quarantined, was writable by the agent. See [Security](../security.md#known-gaps).
- **Disk use.** Every live and every quarantined box holds its own full copy of the lane's history, plus a working checkout, its own temporary and cache files and whatever the agent built in it. Quarantined boxes pile up until you remove them.
- **`.lfsconfig` changes are refused on Codex lanes.** The receive step refuses a Codex lane's commit that adds, changes or removes a `.lfsconfig` file, in any folder and whatever the letter case of its name.
- **An unreadable config file is still read as empty.** A broken config or profile file is an error, but one that exists and can't be read at all (for example because of its permissions) is still read as empty, as in v1.0.0. A later release is planned to make it an error too.
- **The merge check's stop is not identity-checked.** When Yggdrasil stops a merge check that timed out or was replaced, it does not first confirm that the recorded process is still the one it started. A reused process number could be hit only after a crash and a process-number collision. A later release is planned to add the check.
- **Copies of your provider settings stay with each Codex launch.** Every Codex session, the project reviewer's included, runs with its own Codex home, `<state root>/launch/<activation>/codex-home/` (readable only by you). Its `config.toml` holds a copy of your provider's settings, including any credential in its headers, query parameters or address. The links to the shared login are removed when the session ends. Codex writes its own files there too, which may hold anything the agent saw. Nothing removes them when the session ends. A Codex builder's relay also keeps every request it ran, with the text of any file the agent handed in, and every answer, unredacted, under `<state root>/output/<activation>/relay/`. Once no Codex session is running, you may delete those `codex-home` folders and `relay` folders; a new launch writes fresh copies. Leave them out of backups and bug reports. See [Security](../security.md#secrets).
- **Nine commands are not relayed.** A Codex builder's relay does not carry `ygg pause`, `backlog`, `northstar`, `plugins`, `profile`, `standard`, `digest`, `morning-go` or `dashboard`, so a Codex builder cannot run them, even where a Claude Code agent of the same role may. See the [CLI reference](../cli-reference.md).
- **Two sessions refreshing at once rely on OpenAI.** When two Codex sessions refresh a ChatGPT sign-in at the same moment, both send the same refresh token. Codex keeps one result, and the other session relies on OpenAI accepting that token again for a short time (about an hour, by an OpenAI maintainer's account, not documented). A session that still fails its refresh is recovered by launching it again. A login to a different account while sessions run makes the running sessions of the old account fail at their next refresh.
- **Every agent can read the shared login.** Codex and Claude Code agents alike can read Yggdrasil's own Codex login, as they could read your own `~/.codex/auth.json` before, and a Claude Code agent can replace it. A Codex agent cannot write it through its links. Redaction catches the usual token shapes, not a token an agent has reshaped. See [Security](../security.md#secrets).
- **Logout waits only for sessions it can see.** A Codex process that outlived its session can still write a refreshed login back after `ygg codex logout`, though the commands an agent runs inside its sandbox cannot. If a supervisor dies while its Codex still runs, a logout can end that session's sign-in until crash recovery adopts the agent. A Codex agent can make a logout refuse by holding the login folder's lock. See [Security](../security.md#known-gaps).
- **A reviewer on another Codex version or platform has no shared sign-in.** The shared sign-in and `CODEX_API_KEY` reach Codex sessions only on macOS with codex-cli 0.170.0, the pair Yggdrasil has probed. A project reviewer on another Codex version, or on Linux even with 0.170.0, gets neither, so it needs a model provider with its own key; `ygg status` shows `unprobed: no shared sign-in` for its review run. On Linux, `ygg codex login` makes a login that no Codex session uses, and the next step Yggdrasil shows there, for any Codex version, is `Codex's shared sign-in is not probed on linux; use a model provider with its own key`.
- **Some alert texts still say "hub" and "pool".** The alert for an unavailable Codex reviewer speaks of the hub's Codex pool. It means your Codex setup or proxy.

## Upgrading from v1.1.0

In v1.1.0 Codex sessions ran with your own Codex folder (`CODEX_HOME`, or `~/.codex`) and its login. v1.1.1 gives every Codex session its own Codex home: sessions no longer run in your own Codex folder or use its login, and only its model-provider settings are still read from there.

- **A project reviewer on codex-cli 0.170.0 on macOS** that signed in through your own Codex folder, and the Codex builders this release adds, need `ygg codex login` once, unless they sign in with `CODEX_API_KEY` or a model provider with its own key.
- **A project reviewer anywhere else,** on another Codex version or on Linux, the common case if you use Claude Code builders, no longer has a ChatGPT route, because neither the shared login nor `CODEX_API_KEY` reaches it. It needs a model provider with its own key.
- **The lane check refuses new token-shaped strings.** A commit that adds a JSON Web Token, a legacy `sk-` key or a `refresh_token` value to a file is refused, naming the file and line: `<path>: line <n> adds a token-shaped string (a JSON Web Token, an sk- key or a refresh_token); remove it`. A token-shaped string already present anywhere in the repository at a parent of the commit passes (for a `refresh_token`, its value counts, not the spacing around it), so moving, renaming or reformatting a file that holds one is not refused. On a Claude Code worktree lane, the push check's lane check does not judge main's commits again after a lane sync; its separate check for changes to `.github/workflows/` still covers every pushed commit.

The `ygg-codex-sign-in` alert and `ygg doctor` say which of the sign-in cases applies to you.

## Switched off, and rows red by design

Two switches ship off in this release, as in v1.1.0. `dashboard_serve` is off, so `ygg dashboard serve` says it is not in this release; the dashboard file is still written. `t3_live_send` is off, so urgent messages to a T3 session go to the node's inbox like every other message. The acceptance rows of both switches fail by design, among them the 2 rows in `tests/acceptance-a11` for the urgent T3 live send. [Contributing](../contributing.md#rows-that-fail-by-design-in-v111) lists every such row.

## Why Codex builders came later

v1.1.0 planned Codex builders on shared worktrees, which would have let a Codex builder write the home repository's shared git folder and so change another lane's work. That plan was rejected for the design in this release: a private clone per lane, lane rules enforced in the home by code the agent cannot write, and a live run of the real `codex` CLI before release. v1.1.0 shipped without Codex builders, and they ship here.

## How it was checked

Every change was reviewed by a Codex reviewer, and the acceptance suites were written from the release's criteria by a separate test author before the code. The Codex builder suite (`tests/acceptance-v1-1-codex`) runs the real conductor and `ygg` against a stand-in `codex` command. The live rows ran the real Codex CLI.

- The Codex builder suite passed 160 of 160 rows, including the five upgrade rows, which install v1.0.0, reject an exception plan with it, and then continue with this release, and the rows for Yggdrasil's own Codex sign-in.
- The live rows, run by the maintainer on a Mac outside the repository's suites, ran the real `codex` CLI 0.170.0, driven by a scripted model endpoint instead of a real model, and passed: the Codex home held Yggdrasil's own config and only files Codex itself created, no file copied from your own Codex folder, and none of your MCP servers, hooks, rules or skills; a builder could write only in its own box, and its commits reached the project only through the relay and the receive step. The two sign-in probes in `scripts/codex-reprobe` passed on the same Mac with dummy values and the real OpenAI hosts blocked: agents' commands saw no key, and two sessions sharing one Yggdrasil login, refreshing it at the same moment through a local stand-in, both went on to complete a model request with the saved login, while the agents' sandboxes could not write it.
- The v1.1 suite passed 63 of its 65 rows against a wheel installed with `uv tool install`. One row is red by design (the testing-race notice, cut in v1.1.0), and one needs Linux and is skipped on macOS.
- The repair suite (`tests/acceptance-a10`) passed 32 of 32, and the crash-recovery suite (`tests/acceptance-a7`) passed every write-crash row on the Linux test machine.
- The launch and stop crash-safety suite (`tests/acceptance-a8`) and the rest of the crash-recovery suite passed on the Linux test machine, apart from the two crash-recovery tests that also fail on v1.0.0 there (the same two the v1.1.0 notes count).
- The core suite (`tests/acceptance`) passed, apart from two rows that need a leak-scan denylist the test run did not set (see [Contributing](../contributing.md#running-the-tests)).
- The unit tests passed.
