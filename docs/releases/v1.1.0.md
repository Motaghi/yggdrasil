# Yggdrasil v1.1.0

Version 1.1.0 adds a live demo you can run with no AI account, a `ygg --version` command, and fixes for a set of the known defects listed in the [v1.0.0 release notes](v1.0.0.md). It also says plainly which items earlier plans put in v1.1 and which now move to later releases.

## What is in

- **A live demo: `ygg demo`.** It runs the real conductor with scripted stand-in agents in a temporary folder, offline, in about two minutes, with a dashboard page that refreshes while it runs. It needs no account and never touches your config, state, tracker or git settings. See the [CLI reference](../cli-reference.md#demo).
- **`ygg --version`.** Prints `ygg 1.1.0`.
- **`dashboard_refresh_seconds`.** A new setting that makes the dashboard page reload itself. Unset, the page is unchanged. See [Configuration](../configuration.md).
- **Fixed: a false "uncertain" alert at launch.** An agent that exited just as Yggdrasil checked whether it had started could be held with a false "uncertain" alert. Yggdrasil now waits briefly for the exit record and judges from it.
- **A plan under way can't be marked ready again.** `ygg tracker write --kind pid-ready` is refused unless the project is new, its plan was rejected, or an exception plan was rejected and you answered the follow-up decision with `replan`. This stops an approved project from going back to waiting for approval.
- **`ygg send` says what is missing.** With `--from` and no `--kind` it now says `--kind is required with --from`, instead of the misleading user-only refusal.
- **`ygg init` without a terminal says so.** When there is no terminal, it tells you on stderr that the five questions were skipped and their defaults used.
- **More secret-looking names are hidden.** `ygg profile show` now also hides the value under names such as `STRIPE_KEY`, `AUTH_HEADER`, `SESSION_COOKIE` and `COOKIE`. Nothing that was hidden before is shown now, and `linear_team_key` is shown as it is.
- **A broken config file is an error.** A config file that exists but isn't valid YAML, or isn't a mapping, now stops the command with an error that names the file, instead of being read as empty. The same goes for a profile. An empty file is still an empty config. Every command that acts on a project refuses, `ygg stop`, `pause` and `resume` included: with an unreadable file Yggdrasil can't know which folders or tracker it would act on, so it refuses rather than act on the wrong ones. For those three the message says what to do next: fix the file, then run the command again.
- **The team lead's prompt explains its pair reviewer.** It no longer says "Sol pair"; it says what the pair reviewer is and tells the team lead to pass it the project brief.
- **Clearer refusal texts.** Codex builders and projects with more than one repository are now refused with "Codex builds are not in this release" and "projects with more than one repo are not in this release", and the docs and code comments no longer promise them for v1.1.
- **Docs.** The README, Getting started, Configuration, Launchers, Concepts, Security, Contributing and CLI reference pages match this release. [Concepts](../concepts.md) now says how a senior user gets a ruling into the record today.

## Also in this release

- **A longer confirmation window for slow agent starts.** A start that takes longer than the fixed window, for example on a loaded machine, is now confirmed instead of showing as held. The window grows with the machine's load (switch `confirm_window`, shipped on).
- **A Codex reviewer's near-miss verdict is read.** A verdict in one fenced block, a verdict word with stray case or spaces, or a verdict with no `review` key is accepted. A verdict that names a different review is still never adopted.
- **The blockers line in `ygg status` says how old it is.** It names the time of the route map it comes from, and says so when a package or decision changed after it. `ygg status --json` is unchanged.
- **Fewer internal reference numbers in the source comments.** Some were removed; the rest go in a later release.

## Switched off in this release

- **`ygg dashboard serve`.** The switch `dashboard_serve` ships off, because the release machine could not run one of its network checks (it has no non-loopback IPv4 address). The command says it is not in this release. The dashboard file is still written, and `ygg demo` uses it, refreshing every two seconds.

## Cut from v1.1

- **The testing-race notice.** When a work package's criteria change while a senior user is testing it, the senior user is not told. The notice was cut: its delivery depends on older journal-replay behaviour that can bring back a message that was already consumed, and the fixes could not be reviewed in time. It moves to v1.2 together with those replay fixes.

## Known limits that stay

- **Document folders are still a preview.** See [Concepts](../concepts.md#programmes-and-projects).
- **Containment is not here.** Agents still run as your own OS user. Read [Safety](../../README.md#safety) and [Security](../security.md) before you run Yggdrasil on anything that matters.
- **The urgent T3 live send stays off.** Urgent messages go to the node's inbox, as in v1.0.0. The two acceptance rows for it keep their frozen mark `release('fallback-v1.1')` and stay red by design.
- **Codex builders are not in this release.** They are planned for v1.1.1. See the next section.
- **Finish an exception replan before you upgrade.** If a project's exception plan was rejected under v1.0.0 and its follow-up decision is still open, answer it and let the project manager mark the new plan ready before you upgrade. v1.1.0 recognises only follow-up decisions it created itself, so a v1.0.0 follow-up answered after the upgrade leaves the project unable to mark its new plan ready.
- **An unreadable config file is still read as empty.** A config or profile file that is broken is an error now, but one that exists and can't be read at all (for example because of its permissions) is still read as empty, as in v1.0.0.

## What moved out of v1.1

Earlier plans and the v1.0.0 notes placed these in v1.1. They are not in this release.
| Item | Why it moved | Target |
|---|---|---|
| Containment: an OS sandbox per agent, a broker running as a separate OS user, per-launch session tokens, sealed logs | An architecture change of its own | Its own spec, release set later |
| Plugin marketplaces | Packaging and outward-facing submissions | v1.2 |
| The security list of 16 Nov: Codex write broker, credential broker, hash-anchor choice, issue-lookup creator check, T3 server credentials, T3 ownership re-check, medium-severity hardening | Each needs its own design; the two brokers belong with containment | v1.2 for the hash anchor, issue lookup, T3 credentials and T3 re-check; the brokers with containment |
| Codex builders (project managers, team leads, workers and senior users on Codex) | Making the Codex sandbox work meant letting Codex builders write to the home repository's shared git folder, which would let one builder change another lane's work. That is a lane escape, so Codex builders wait for a design that gives each Codex lane its own private clone | v1.1.1 |
| The project manager runs the approved test commands | Widens its permissions and needs a new agreement version and renewed consent | v1.2 |
| A senior user's ruling gets into the record by itself | It needs new machinery to link an answered decision to a ruling. Today: the senior user raises a decision, you answer it with `ygg decide` and record the ruling with `ygg ruling record` | v1.2 |
| Full tracker plugin interface | Not started | v1.2 |
| Multiple hosts for workers | Not started | Its own spec, release set later |
| First-class document folders with per-package review | Not started | v1.2 |
| Projects with more than one repository | Not started | v1.2 or later |
| Linear webhooks | Not started | v1.2 or later |
| Wider read-only git shapes for agents, and message retract | Not started | v1.2 |
| Owner binding of the approved home | Not started | v1.2 |
| The 17-minute gap after a decision answer | The code owes the work at once, so the cause is not in that path and is not found yet | v1.2, as an investigation |
| The urgent T3 live send, with its admission checks | The checks need ownership evidence and stop, pause and revoke cases that could not be specified and built in time; the switch stays off | v1.2 |
| A lane sync that hits a conflict can be resolved | A conflict aborts the sync and leaves the lane unchanged, and nothing resolves it yet | v1.2 |
| The retry cap resets its count after edits between runs | Not built | v1.2 |

| The testing-race notice (see "Cut from v1.1") | Cut | v1.2 |

The v1.0.0 notes still promise some of these for v1.1. They stay as the record of v1.0.0.

## How it was checked

Every change was reviewed by a Codex reviewer, and the new acceptance suite for v1.1 was written from the release's criteria by a separate test author before the code. The release was checked as a user gets it: a wheel built from the release tree was installed with `uv tool install` into a fresh tool folder, and every suite ran against that install with the shipped switches (a few acceptance tests switch a feature on for themselves to test it).

- The v1.1 suite passed 64 of its 65 rows. The one red row is the cut testing-race notice.
- The A11 suite failed only rows that are red by design: the 8 Codex-builder rows (planned for v1.1.1), the 2 urgent T3 rows (planned for v1.2), and the 12 rows of the switched-off dashboard server and its network check.
- The A11.1 suite passed 138 of 138, and the A7 to A10 crash-recovery and repair suites passed apart from the two crash-recovery tests counted in the next line.
- Eleven tests failed on the Linux test machine: nine unit tests and two crash-recovery tests. Each one also fails on v1.0.0 under the same conditions, so none is new in v1.1.
- The core suite passed apart from two rows that need a setting the test machine lacked, and five rows that timed out under load and passed when run alone.
- A red-team review and a privacy review read the exact published tree before release.
